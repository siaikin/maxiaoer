# 蚂小儿图文发布

使用蚂小儿桌面应用已有的账号和发布引擎。先将图片保存到素材库，再用素材 ID 准备和提交内容。桌面应用及电脑必须保持运行；定时任务也由本机执行。

## 找到连接和账号

发现当前已连接的蚂小儿 MCP 工具，使用实际工具名；客户端可能给下列名称加前缀。工具的实时输入结构优先于本文示例。

- `list_platforms`：读取平台限制和发布配置项。
- `list_accounts`：根据用户指定的平台、昵称或账号 ID 选定目标；无法唯一确定时再询问，不擅自选择全部账号。过期账号需要在桌面应用中重新登录。
- `get_account_collections`：只有需要指定合集时读取，以返回的合集对象填写账号配置。
- `list_topic_presets`：用户指定已保存的话题合集时读取。

连接不可用时可用本技能的 `scripts/maxiaoer-client.mjs info` 检查本机连接文件；此命令不显示令牌。默认读取 `~/.maxiaoer/mcp.json`，可用 `MAXIAOER_CONNECTION_FILE` 或 `--connection FILE` 指定另一文件。不要在回复或日志中输出连接令牌。应用启动后才能连接；没有 MCP 工具时说明需启用连接，不把上传客户端当成发布接口。

## 图片先入库

所有新增图片都要导入并记录返回的 `id`。`prepare_publish` 的 `materialIds` 只接受素材 ID，不接受本地路径、附件占位符或 URL。

- **现有素材**：用 `list_materials` 找到用户选定的素材；按实际返回的 ID 使用。
- **图片链接**：调用 `import_material({ url, filename? })`。使用能下载到图片本身的 HTTP/HTTPS 链接；网页链接、需要额外登录的链接、内网地址不保证可导入。
- **已有 Base64 或 Data URL**：调用 `import_material({ base64, filename? })` 或 `import_material({ dataUrl, filename? })`，Data URL 支持 Base64 和百分号编码。`url`、`base64`、`dataUrl` 三者必须只传一种。
- **附件、生成图片、本机文件**：已有可读本地副本时，运行下面的上传脚本。脚本读取文件字节，通过本机 `/materials/upload` 保存到素材库；发给服务端的是字节和文件名，不是原始路径。不要让模型手写大段 Base64，也不要将原图完整编码打印进上下文。

上传脚本需 Node.js 22 或更新版本，无第三方依赖；保留同目录的 `mcp-connection.mjs`。从技能所在目录运行（也可用脚本绝对路径）：

```bash
node scripts/maxiaoer-client.mjs import '/实际可读的图片文件.png' '/另一张图片.jpg'
```

每个成功的导入会输出一行 JSON，其中包含素材 `id`。多文件导入若中途失败，保留已成功返回的素材，修正后只重试失败部分。若聊天附件只有不透明引用且无法读取其文件或下载地址，说明缺少可读取的来源，请用户提供可访问的图片文件或链接；不要猜测附件对应的路径。

单张原图上限为 **25 MiB**。库中保存原图副本；JPEG、PNG、GIF、WebP 保留格式，单页 TIFF、静态 AVIF、SVG 会生成 PNG 发布副本。多页 TIFF 和动画 AVIF 会被拒绝，避免丢页或丢帧；BMP、HEIC 不作支持保证。导入结果中的尺寸、类型和大小用于后续平台校验；导入成功不代表满足所有平台限制。

## 准备与提交

根据用户的明确要求和会话中已确认的选择填写 `prepare_publish`：

```text
{
  title, content, materialIds, topics, accountIds,
  overrides: { 平台ID: { title?, content?, materialIds?, topics? } },
  settings: { 账号ID: { 配置项: 值 } },
  scheduledAt?: 带时区的ISO时间
}
```

`overrides` 中未指定的字段沿用通用内容。账号配置以 `list_platforms` 返回的字段和允许值为准；省略的配置按应用中的“使用上次选择”或默认值补齐，检查返回的预览。话题传不带 `#` 的数组。用户指定时间时，按其时区解析成明确的时间，例如 `2026-10-14T10:00:00+08:00`；只在日期或时区确实有歧义时询问。

检查返回的 `valid`、`errors` 和 `preview`。平台会自动过滤超出其大小或尺寸限制的图片；`preview.materialIds` 是实际将发布的图片，`skippedMaterials` 与 `warning` 说明跳过原因，向用户清楚说明这些差异。素材库原图仍保留，其他平台独立过滤。如果用户明确要求全部图片都必须发布，不要用过滤后的内容代替该要求。校验失败时修正能根据已有要求确定的问题；不要为了通过校验擅自丢图、改账号、改变发布时间或改变文案含义。需要用户决定的内容先指出具体差异。修改后重新准备，使用新返回的 `draftId`。

用户已明确要求发布，账号、内容和时间也明确时，校验通过后直接调用 `publish({ draftId, requestId })` 完成其授权，不因为准备与提交是两个工具而强制再问一次。用户只要求准备、校验或看预览时，交付预览并保留草稿，不提交。

为每次新发布生成唯一的 `requestId` 并保留。相同发布因响应丢失或网络中断需要重发时，使用**原 `draftId` 和原 `requestId`**；不要重新准备一份相同内容来绕过去重。一份草稿只能创建一次发布任务，服务端返回 `reused: true` 表示复用了已有任务。

## 结果和失败重试

`publish` 返回的是任务，不代表所有平台发布成功。使用 `get_publish_jobs` 查询返回的任务 ID，按账号说明成功、失败、等待或定时状态；只有成功结果才标为已发布，存在作品链接时一并提供。定时任务注明具体时间和时区，并提醒应用与电脑届时需运行。应用重启会恢复尚未执行的 `pending` 任务；中断时正在执行的 `running` 任务会标为失败，先核对平台结果再决定重试，不重新建立相同稿件。

对失败或跳过的子任务，可调用 `retry_publish_task({ jobId, taskId, allowDuplicate?, verifiedNotPublished? })`：

- 用户已要求完成发布时，尚未启动的预检失败可在原授权范围内修正后重试，只操作尚未成功的指定子任务；用户仅要求查询状态时不重试。
- 凡任务已有 `startedAt`（曾经开始执行），或存在作品 ID／链接、超时或无法确认的错误提示，都先到对应平台核实是否已发布；仅有明确未发布证据时设置 `verifiedNotPublished: true`。不能只凭错误信息推断未提交，也不能把重试请求本身的响应丢失视作再次重试的依据。无法核实时停在该任务并说明原因，不能盲目重试或新建同稿。
- 只有用户已明确允许重复发布，才对因重复内容跳过的任务设置 `allowDuplicate: true`；会话里已有这项授权就沿用，无需重复询问。
- 重试受理后继续查询结果。同一原因再次失败时，停止自动重试，报告具体错误与需要处理的条件。
